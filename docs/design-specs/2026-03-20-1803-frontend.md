# Frontend

**Created:** 2026-03-20 **Implementation Plan:** TBD

## Overview

**What:** A minimal React frontend for the video encoder — single-page utility UI where designers drop a video, watch encoding progress, and download the output files.

**Why:** Phase 3 of the video encoder app. The server and encoding pipeline are built; this gives the design team a self-service interface instead of CLI commands.

**Type:** Feature

---

## Requirements

### Must Have

- [ ] Drag-and-drop upload zone with click-to-browse fallback
- [ ] Client-side file validation (max 30MB, `video/*` mimetype) with inline error messages
- [ ] Indeterminate progress indicator during file upload
- [ ] Determinate progress bar (0–100%) during encoding, driven by SSE
- [ ] Two download buttons on completion (AV1 and H.264)
- [ ] Inline error display for server-side failures with "Try again" reset
- [ ] Vite dev proxy to Express server on port 3000
- [ ] Production build served as static files by Express

### Nice to Have

- [ ] Preset dropdown (when multiple presets exist)
- [ ] Per-codec progress breakdown
- [ ] Post-download reset button for new uploads

### Out of Scope

- Routing / multiple pages
- Mobile / responsive layout
- Batch uploads
- Cancel in-progress encoding
- Authentication

## Design Decisions

### Layout: Single Centered Card

**Options considered:**

1. **Single centered card** — Content swaps between states (upload → progress → download). Compact and focused.
2. **Stacked sections** — Upload always visible, results stack below. Better for batch, more complex for single-file.
3. **Stepper/wizard** — Numbered steps with indicators. Over-engineered for a 3-step utility.

**Decision:** Option 1. One card, state-driven content. Matches "minimal utility" goal. Revisit if batch uploads are added.

### State Management: Flat useState

**Options considered:**

1. **Flat state variable** — Single `status` string drives rendering. Simple, linear flow.
2. **useReducer** — Formal reducer with action types. Adds ceremony for 5 linear states.

**Decision:** Option 1. A `useState` for status plus companion values (`jobId`, `progress`, `error`, `outputs`) is sufficient for a linear flow.

### SSE Connection: Custom Hook

**Options considered:**

1. **Custom hook (`useEncodingProgress`)** — Encapsulates EventSource lifecycle, returns reactive state. Clean separation from UI.
2. **Inline useEffect** — Fewer files, but mixes SSE logic with rendering.

**Decision:** Option 1. Keeps the component focused on rendering.

### Preset Selection: Skipped for Now

Only one preset exists ("Header Video"). The dropdown adds UI complexity with no current value. The upload hardcodes `presetId: "header-video"`. When additional presets are added, introduce a dropdown and fetch presets from the server.

## App States

The card renders different content based on a single `status` value:

| State             | Card Content                                                                                                |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| `idle`            | Drop zone with dashed border. "Drop a video here or click to browse." Hidden file input triggered on click. |
| `validationError` | Same drop zone, plus inline error below (e.g., "File exceeds 30MB limit"). User can drop/select again.      |
| `uploading`       | File name, indeterminate progress bar, "Uploading..." label.                                                |
| `encoding`        | File name, determinate progress bar (0–100%), "Encoding... X%" label. SSE connection open.                  |
| `done`            | File name, success message, two download buttons: "Download AV1" and "Download H.264".                      |
| `error`           | File name, inline error message from server, "Try again" button resets to `idle`.                           |

`validationError` is a sub-state of idle — the drop zone stays interactive so the user can retry without an extra click.

## SSE Hook Behavior

`useEncodingProgress(jobId: string | null)` → `{ status, progress, outputs, error }`

- Opens `EventSource` to `/api/encode/:jobId/progress` when `jobId` is non-null
- Parses each SSE `data` event as JSON: `{ status, progress, outputs }`
- Updates return values on each event
- Server closes connection on `done` or `error` — hook cleans up `EventSource`
- On unmount, closes `EventSource` if still open
- On `EventSource` `onerror`, sets status to `error` with "Lost connection to server" — no auto-reconnect, user hits "Try again"

## Dev Setup

- Vite + React + TypeScript scaffolded in `client/`
- ShadCN initialized with Tailwind CSS
- Vite dev server on port 5173, proxies `/api` to `http://localhost:3000`
- Production: `vite build` → `client/dist/`, served by Express as static files

## Acceptance Criteria

- [ ] User can drag-and-drop a video file onto the upload zone
- [ ] User can click the upload zone to browse for a file
- [ ] Files over 30MB show an inline validation error without uploading
- [ ] Non-video files show an inline validation error without uploading
- [ ] Upload triggers a POST to `/api/encode` and shows an indeterminate progress indicator
- [ ] After upload, a determinate progress bar reflects SSE encoding progress (0–100%)
- [ ] On encoding completion, two download buttons appear ("Download AV1", "Download H.264")
- [ ] Clicking a download button downloads the correctly named file
- [ ] Server errors display inline with a "Try again" button that resets to idle
- [ ] Lost SSE connection displays an error with "Try again"
- [ ] Vite dev proxy forwards `/api` requests to Express on port 3000
- [ ] `vite build` output is servable as static files by Express
